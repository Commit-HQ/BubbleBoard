# Event photo format 1

Implemented 2026-09-20. Annual albums, persistent drafts and republication are excluded. No production deployment or physical-phone pilot is implied by implementation.

## Encryption and rendering

An event has a fresh AES-GCM key. Its raw key is sealed with the classroom Group Key (`event-key`). The event manifest (`event-content`) contains format, title, date, description and ordered photo IDs/dimensions, each photo optionally carrying up to 300 characters of the teacher's own words. The description is a checked notice document (`src/lib/notices.ts`), read through the same reader boards use for notices and rendered with the app's own components, never as HTML; a plain string, as events published before that carried, is read as paragraphs. Each photo is one binary AES-GCM envelope (`event-photo`) in private R2. Inside it are a compressed base (WebP, or JPEG where a browser can't write WebP) with every marked rectangle overwritten, its encoding named beside it, encrypted lossless PNG face patches, anonymous recipient grant envelopes and a Staff-Key envelope containing labels, geometry and all patch keys. Original files and camera metadata are not uploaded. A device composes the photo it shows from the base and the patches it can open, and compresses that too: the composite is never uploaded, and what a family saves from the viewer is a JPEG of it.

Every new context uses additional authenticated data `['BubbleBoard',1,purpose,event,photo-or-null,part-or-null]`; existing card/data contexts remain byte-for-byte unchanged. `event-face` protects one patch with a fresh key. `event-grant` holds that patch key encrypted with each eligible Family Key. Group-visible patch keys are inside the event package. `event-staff` opens patch keys only for staff. Readers validate the manifest and photo dimensions; inaccessible/damaged patches leave the covered base in place. Download uses the same rendered PNG as the gallery. Event cards contain no original thumbnail.

Face patches zero all RGBA channels where any other cover overlaps. Overlap cells are grouped by the exact set of covering faces and encrypted separately. A family gets an overlap key only if every involved face is group-visible or belongs to that family. An overlap key is group-visible only if all involved faces are group-visible. Areas involving an unassigned/permanently covered face never produce a patch. Bounding-box gaps in overlap patches are zero in all channels. Private face patches and overlap patches use lossless encoding: they carry faces, and the exact zeroes at their edges are what keeps a boundary where the geometry puts it. The base is compressed, because every covered rectangle is overwritten with a flat colour and its sticker drawn on before anything is encoded, so no face pixel reaches the encoder and there is nothing for compression to bleed; the reader accepts only the encodings the device may write. Caps: the installation's photo limit (30 by default, `PUBLIC_EVENT_PHOTOS`), 100 covers/photo, 400 patches/photo, 32 000 bytes of manifest, 32 MiB encrypted photo payload and 4 MiB of prepared gallery for each photo the limit allows — a photo of the editor's size packages to well under a megabyte, and its patches are what grow when it is full of children. The device measures the sealed manifest before it uploads anything, so words too long are refused before the photos are sent.

## Consent and publication

`photo_families` projects each child's name under the linked Family Key using `photo-label` with child/family IDs. Admin child changes update projections atomically; staff sync backfills existing catalogs under an exact catalog revision. Family updates can only target an existing row belonging to their authenticated family and compare the row revision. An admin records the same choice from the child's page, or when a child is added, for every family card linked to the child: that write also names the row revision it read, and a parent's change made meanwhile empties the revision instead, which fails the whole child change as stale. `photo-choice` authenticates the child/family combination. Missing, malformed and unreadable choices are private. Group sharing requires an explicit true choice from every family actually linked in the decrypted catalog. Staff ignore injected/unrelated IDs.

A global consent revision advances on choice changes and projection insert/delete. Preparation reads consent and catalog revisions. New event IDs reserve a draft owned by the current credential. Uploads are immutable, counted through `stored_objects`; HEAD checks exclude uploads that were counted but never reached R2. The publication transaction names every object and changes draft to published, with a database trigger comparing catalog and consent revisions. A changed revision fails the entire transaction and requires a new preparation/preview. Lost-response retries use the same immutable draft and cannot duplicate the event or its push. A failed R2 write requires preparing a new draft; old unreferenced objects are cleaned up. Drafts expire after one day.

Published choices are snapshots: subsequent consent edits do not change old events. Removal/expiry denies new reads immediately; named-object deletion triggers and daily cleanup reclaim the encrypted bytes. Duration is 1/3/7/14/30/60/90 days from publication. No hidden archive. Author or admin can remove an event, subject to current classroom access. Every fetch requires an active session and current classroom membership, with private/no-store responses. The gallery releases object URLs and hides expired events; already downloaded copies cannot be recalled.

## Detection and verification

The pinned short-range BlazeFace model stays local in a classic worker. Full-image and overlapping half-size crops are scanned at 0/90/180/270 degrees, then duplicate boxes suppressed before padded editor covers are created. This improves scale/orientation coverage without another model dependency; no accuracy guarantee is made. On the bundled classroom photo this found six faces versus three in the previous single pass. Manual correction and teacher review are still required.

Unit/integration tests cover consent intersection, wrong keys/contexts, overlap pixel sanitization, stale publication rollback, wrong-classroom reads, missing uploads, idempotent publication and cleanup. `/editor-check` is development-only and includes a real browser canvas/encryption check for two families, outsider, sanitized patch pixels and a family authorized for both overlapping faces. The latter reproduced and fixed a yellow overlap fragment in previews. Physical iOS/Android performance, representative real galleries and pilot acceptance remain outstanding.
